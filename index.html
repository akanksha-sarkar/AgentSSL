AgentSSL: Can MLE Agents
Leverage Unlabeled Data?

Ethan Lin*, Akanksha Sarkar*, Ziang Liu, Kristin Branson, Jennifer J. Sun
*Equal contribution
Paper Code arXiv
TL;DR MLE agents can discover strong programs that leverage unlabeled data, but reliable program selection remains the bottleneck.

MLE agents reduce engineering cost but rely on labeled data; semi-supervised learning reduces annotation cost but needs human engineering. We ask whether agents can reduce both, and find they can discover strong programs that leverage unlabeled data.

Abstract

Acquiring high-quality labeled data and engineering effective learning pipelines are two critical bottlenecks to applying machine learning systems in new domains. Although recent MLE agents have shown promise in automating pipeline design, their behavior has been studied almost exclusively in fully supervised settings. In many domains, however, labeled data is expensive while unlabeled data is abundant. In this work, we study agents in the semi-supervised learning (SSL) regime by framing SSL as a program search problem and exploring how agents navigate this space under limited supervision. Our analysis focuses on three questions: (1) whether agents can effectively leverage unlabeled data, (2) how they leverage it and what strategies they discover, and (3) whether they can adapt these strategies to specific domains. We find that agents can leverage and synthesize SSL strategies spanning decades of SSL research, achieving performance comparable to, and in some cases outperforming, established human-engineered SSL methods. We further validate these observations on real-world ecological datasets, highlighting both the challenges and opportunities of transferring agent-discovered strategies beyond controlled benchmarks.

Contributions

1) AgentSSL: we formulate semi-supervised learning as a structured program-search task for MLE agents.

2) Strong programs: agents autonomously discover SSL programs competitive with, and in several cases outperforming, established SSL baselines.

3) Systematic analysis: agents exploit unlabeled data, explore ideas across classical and modern SSL, and produce diverse, performant solutions.

4) An open problem: we identify reliable program selection as the key bottleneck, with an empirical analysis of existing proxy metrics.

5) Real-world ecology: we evaluate AgentSSL on animal detection tasks, showing both the potential and the challenges of reducing annotation cost in practice.

Method

We frame SSL as a program search problem using LLM-based agents.

Given a small labeled set and a larger unlabeled corpus, an LLM-based agent writes SSL programs. Each program is scored by an evaluator using either unsupervised SSL metrics or noisy validation feedback, and that fitness guides iterative refinement (Phase I). From the resulting candidate programs, one must then be selected without access to test labels (Phase II).

We evaluate AgentSSL on six image-classification SSL benchmarks (DTD, SUN397, RESISC45, Retinopathy, CLEVR, KITTI) and two real-world ecological detection tasks (WildFin, BuckTales).

Results

Can agents beat human-engineered SSL?

Across datasets and shot settings, the best agent solution (Abest) is generally comparable to the best human-engineered SSL baseline (Hbest), and outperforms it on several, by up to +15.8 points on Retinopathy.

The bottleneck is not generating good SSL programs, but selecting among them. When unsupervised selection metrics correlate with test accuracy, AgentSSL keeps much of its oracle performance; when they don't, it drops substantially.

Analysis

Do agents actually use unlabeled data?

We fix the top program discovered by AgentSSL and vary only the size of the unlabeled corpus at evaluation time. Performance generally improves as more unlabeled data becomes available while the labeled set stays fixed, so the discovered programs rely on structure in the unlabeled data itself.

How do agents use unlabeled data?

Rather than converging to a single method family, agents explore a broad range of SSL paradigms, from pseudo-labeling and consistency regularization to graph-based methods, and often combine several within one program. The resulting programs are also complementary: high-performing programs built on different SSL strategies confidently pseudolabel different subsets of the unlabeled images.

Are programs tailored to their domain?

Agents can discover dataset-specific strategies instead of relying on one fixed SSL recipe. The best program for each dataset does not generalize to other datasets, evidence that it is tailored to its own domain.

On Retinopathy, the best program trains no classifier at all. It uses frozen DINOv2 features, nearest-neighbor evidence, class prototypes and an explicit ordinal bias, matching the fact that labels are ordered disease-severity levels. It beats the next-best baseline by 15%.

Real-world ecology

We evaluate AgentSSL on animal detection from two ecological pipelines, WildFin (fish) and BuckTales (antelope), against the domain experts' YOLOv8 pipelines using small labeled subsets.

On WildFin, agents outperform the low-label expert baseline and approach the full-data pipeline. On BuckTales they only match it: the expert solution relies on very high-resolution inputs, while agents spend their budget on more complex tiling and SSL strategies.
